# Clipsync

A responsive Next.js App Router clipboard workspace and editorial landing page. Uses TypeScript, Tailwind CSS 4, Framer Motion, Lucide, React Hook Form, Zod, and Supabase Auth/Postgres/Realtime.

## Run

Requires Node 22 or later. Run `npm install`, copy `.env.example` to `.env.local`, then run `npm run dev`. Without Supabase configuration the app shows real empty and setup states, not simulated devices or transfers. `npm run typecheck` and `npm run build` validate and export the application to `out/`.

## Enable live synchronization

1. Create a Supabase project. Run `supabase/migrations/001_clipsync.sql` in its SQL editor. The migration requires pg_cron and pgcrypto; use a fresh project or adapt the migration before applying to an existing database.
2. Set `NEXT_PUBLIC_SUPABASE_URL` and `NEXT_PUBLIC_SUPABASE_ANON_KEY` in `.env.local`. Use only the public anon/publishable key, never a service-role key. Rebuild after changing these public variables.
3. Enable email authentication. Set the Site URL to your HTTPS origin and allow your `/dashboard/` redirect URL. Configure a production email provider and authentication rate limits in Supabase.
4. Sign in with the same email on both browsers. On device A, open Devices → Connect a device, name the device, and generate a code. On device B, follow the same flow, enter A’s code, and request connection. Back on A, confirm. On B, choose Verify connection.
5. Send text from the overview. On the receiving device choose Copy, then use the OS paste command. Acknowledgements reflect a browser receiving the clip, not an OS clipboard write.

## Architecture and security boundaries

UI lives in `components/`, synchronization in `hooks/use-clipsync.ts`, validation and Clipboard API behavior in `lib/`, database authorization in `supabase/migrations/`. Static routes are generated by the Next App Router. Supabase supplies the actual backend; no server secrets or service-role credentials are needed in this client.

Pairing uses a 48-bit random code, stores only its SHA-256 hash, expires after five minutes, and requires the same authenticated account on both devices plus explicit confirmation. A maximum of ten pairing requests per account per hour and thirty clips per minute is enforced under an account-level advisory lock. RLS isolates accounts. Column grants prevent clients changing device owners or creating authorization records outside the RPCs. Every send and receipt checks active device authorization. Revocation prevents future sends and receipts; sign out all sessions if an account session is compromised. Devices are account metadata, not independent cryptographic principals: a trusted authenticated account can manage all its devices and read its clips. This release does not claim resistance to a stolen account session.

No end-to-end encryption is claimed. HTTPS protects transport; configure Supabase infrastructure encryption, backup retention, SMTP, auth abuse protection, and monitoring for production. Clipboard text is not written to application logs, notification content, URLs, or browser persistent storage. Text necessarily exists in browser memory while displayed. History is opt-in; transient delivery text expires in 24 hours. History retention is 1/7/30 days for new clips; pinning does not extend it. Hourly pg_cron removes expired records, with immediate expiry filtering in database read policies.

Realtime refreshes the signed-in account’s list, with a 30-second refresh fallback. Clips are distinct append-only sends, so concurrent text is preserved rather than silently overwritten. No offline clipboard queue is stored. Retry manually after reconnecting. Pause is browser-session scoped. It stops sending and receipt acknowledgements; account data can still be fetched while paused. Permission is checked per browser; receiving never silently replaces the system clipboard.

## Platform support

Browser/manual mode works in modern browsers over HTTPS. Clipboard reads/writes require supported APIs, permissions, and user interaction. Mobile pages can suspend in the background. Continuous desktop monitoring requires a browser extension with suitable integration or a native companion; background mobile clipboard behavior requires native integration subject to OS restrictions. Companions are not included. The web app never claims they are installed.

## Deployment

`npm run build` creates a static export in `out/`; host it on an HTTPS static host with directory index routing. The Supabase endpoint is an external authenticated backend. The public project variables are baked into the build. Add every deployed origin to your Supabase auth redirect allowlist. Live multi-device verification requires an actual Supabase project and two signed-in browser sessions.
